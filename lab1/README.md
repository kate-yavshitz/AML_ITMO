# Лаба 1: Раннее фузирование модальностей (аудио + текст) для детекции афазии

## Задача

Бинарная классификация диктора по фонограмме: **афазия / нейротипичный контроль**.
Две модальности — аудио и текст (транскрипт) — объединяются **ранним фузированием
через cross-attention** (конкатенация не используется, по требованию лектора).

В курсовой работе использовалось позднее фузирование; здесь совместное
представление модальностей строится **до** классификатора.

## Данные

Три источника (папка `sound/` монтируется как `data/raw/`):

| Папка | Источник | Роль |
|---|---|---|
| `aphasia/` | RuAphasiaBank, пациенты (типы: cma, sa, efa, smta, sema, ra) | train + val + test |
| `nt_train/` | RuAphasiaBank, контроль (~20 дикторов) | train + val + test |
| `nt/` | собственные собранные записи (~23 диктора) | **только train** |

**Почему `nt/` не попадает в test/val**: она записана в других условиях, чем
RuAphasiaBank. Если дать модели тестироваться на ней, она может выучить канал
записи вместо патологии («студийная запись → control»). Честный тест возможен
только внутри RuAphasiaBank, где пациенты и контроль записаны одинаково.

Имена файлов содержат метаданные, которые парсятся автоматически
(`src/metadata.py`): `sp10_m_0_cma_s_22.wav` → диктор sp10, пол m, тип
афазии cma, тяжесть s. Третье числовое поле — возраст (0 = не указан).
Все участники эксперимента старше 40 лет, молодые — редкие исключения;
фонограммы без указания возраста также записаны с людьми 40+.

### Препроцессинг (librosa)

Все фонограммы приводятся к единому формату и собирается манифест:

```bash
docker run --rm --gpus all -v $(pwd)/data:/app/data \
  lab-aphasia python scripts/preprocess_audio.py
```

моно → ресемплинг 16 кГц → обрезка тишины по краям (`top_db=25`) →
пиковая нормализация −1 dBFS → `data/processed/` + `data/manifest.csv`.

Если готовых транскриптов нет, они автоматически генерируются Whisper'ом
внутри контейнера и кэшируются. Если рядом с аудио лежит `<имя>.txt` —
используется он.

## Архитектура

CrossAttentionFusion (раннее фузирование):

- **wav2vec 2.0 XLS-R-300m** (`facebook/wav2vec2-xls-r-300m`, заморожен) →
  последовательность аудио-фреймов `T×1024`, ~50 фреймов/с. Та же модель,
  что в курсовой работе (там — с Random Forest и поздним слиянием), что
  делает сравнение «позднее vs раннее фузирование» чистым.
  В отличие от Whisper, жёсткого окна 30 с нет: запись (до `max_audio_sec`
  секунд) режется на фрагменты по `fragment_sec` (под VRAM), каждый фрагмент
  прогоняется через энкодер, фреймы склеиваются в полную временну́ю ось.
  Нормализация входа — один раз на всю запись, до нарезки.
- Whisper-small используется **только как ASR** для транскриптов.
- RuBERT-tiny2 (заморожен) → последовательность текстовых токенов `L×312`
- Linear projection `1024→256` (аудио), `312→256` (текст)
- **Cross-attention: Q = текст, K = V = аудио** (вариант, предложенный на лекции)
- Residual + LayerNorm → masked mean-pooling → MLP → 2 класса

Эмбеддинги обеих модальностей считаются один раз и кэшируются на диск
(аудио — в float16) — обучение головы занимает минуты и помещается
в 6 ГБ VRAM.
Функция потерь — взвешенная кросс-энтропия (дисбаланс классов), AdamW +
cosine annealing, early stopping по val F1.

## Протокол оценки

**StratifiedGroupKFold (k=5) по дикторам**: все записи одного диктора —
в одном подмножестве (нет утечки голоса); test/val только из RuAphasiaBank.
Контрольных дикторов в RuAphasiaBank всего ~20, поэтому одиночный сплит дал
бы в test лишь ~3 дикторов контроля — кросс-валидация использует данные
надёжнее. Итоговые метрики:

- **out-of-fold (OOF)**: каждый диктор предсказан ровно один раз моделью,
  которая его не видела — главный результат;
- mean ± std по 5 фолдам — оценка стабильности.

**Абляция** (обоснование ценности собранных записей `nt/`):

- **E1** (baseline): `use_nt: false` — train только на RuAphasiaBank;
- **E2** (основной): `use_nt: true` — train на RuAphasiaBank + `nt/`;
- разница OOF-метрик E2 − E1 = вклад собранного корпуса.

## Результаты

**Версия v2 (wav2vec2, полные записи до 300 с)** — основной результат:

| Вариант | OOF accuracy | OOF F1 | OOF ROC-AUC | acc по фолдам | F1 по фолдам | AUC по фолдам |
|---|---|---|---|---|---|---|
| E1 (без nt) | 0.903 | 0.944 | 0.932 | 0.899 ± 0.080 | 0.935 ± 0.061 | 0.959 ± 0.028 |
| E2 (с nt) | 0.887 | 0.935 | 0.915 | 0.887 ± 0.036 | 0.936 ± 0.020 | 0.943 ± 0.039 |

Абляция показала, что добавление собственных записей нормы (102 фонограммы,
иной канал записи) не даёт прироста качества: различие OOF-метрик ≤1.6 п.п. —
в пределах вариативности между фолдами (≈3 записи из 186). При этом E2
заметно стабильнее между фолдами (std accuracy 0.036 против 0.080) —
дополнительные данные выступают скорее стабилизатором обучения. Между
повторными запусками при фиксированном seed метрики варьируются в пределах
±0.005 (недетерминированные операции cuDNN).

Результаты версии v1 (аудио-энкодер Whisper, окно 30 с): E2 — OOF accuracy
0.968, F1 0.981, ROC-AUC 0.997 (по фолдам: acc 0.970 ± 0.019,
F1 0.982 ± 0.012, AUC 0.999 ± 0.002). v1 смотрела только первые 30 с записи;
v2 обрабатывает запись целиком, что методологически честнее, но сложнее
(mean-pooling по ~9 тыс. фреймов размывает локальные маркеры, а признаки
self-supervised XLS-R слабее ASR-supervised признаков Whisper).

### Сравнение с бейзлайном (курсовая работа, позднее слияние)

| Модель | Данные | Уровень | Метрика |
|---|---|---|---|
| Wav2Vec 2.0 + Random Forest (курсовая) | RuAphasiaBank | файлы (n=58) | F1-macro 0.922 |
| Wav2Vec 2.0 + Random Forest (курсовая) | RuAphasiaBank | дикторы (n=18) | F1-macro 0.832 |
| Лексика (MTLD + GB) (курсовая) | RuAphasiaBank | дикторы (n=18) | F1-macro 0.459 |
| Позднее слияние: Wav2Vec + MTLD + RF (курсовая) | RuAphasiaBank | дикторы (n=18) | F1-macro 0.886 (5-fold CV), 0.800 (LOO) |
| **Раннее фузирование: cross-attention + wav2vec2 (эта работа)** | RuAphasiaBank + nt/ | записи, OOF по 89 дикторам | F1 0.935–0.944, ROC-AUC 0.915–0.932 |

Сравнение ориентировочное: в курсовой оценка на уровне дикторов (n=18,
F1-macro), здесь — на уровне записей с OOF-предсказаниями по всем дикторам
RuAphasiaBank (F1 бинарный по классу «афазия»); контрольная группа также
расширена собранными фонограммами `nt/`. Акустический энкодер в обеих
работах один и тот же (XLS-R-300m), поэтому разница отражает именно
способ объединения модальностей: позднее слияние + RF против раннего
cross-attention.

## Требования

- Docker + NVIDIA Container Toolkit (на Windows — Docker Desktop с WSL2-бэкендом;
  драйвер 512.78, CUDA 11.6 — базовый образ подобран под неё)
- ~6 ГБ свободной VRAM (XLS-R-300m fp16 + Whisper-small + RuBERT-tiny2)
- ~10 ГБ на диске под кэш эмбеддингов (float16, до 5 мин на запись)
- Скачиваемые модели: XLS-R-300m (~1.2 ГБ), Whisper-small (~461 МБ),
  RuBERT-tiny2 (~117 МБ). Кладутся в `data/.cache` (через XDG_CACHE_HOME) —
  при смонтированной `data/` скачиваются один раз.

## Запуск через Docker (WSL / Windows)

```bash
# сборка (один раз)
docker build -t lab-aphasia .

# полный цикл: препроцессинг -> обучение (5 фолдов) -> визуализация отчёта
# папку D:\AML_labs\sound монтируем как /app/data/raw
docker run --rm --gpus all \
  -v "D:\AML_labs\sound":/app/data/raw \
  -v $(pwd)/data:/app/data \
  -v $(pwd)/checkpoints:/app/checkpoints \
  -v $(pwd)/reports:/app/reports \
  lab-aphasia
```

> В WSL путь к диску D: выглядит как `/mnt/d/AML_labs/sound`:
> `-v /mnt/d/AML_labs/sound:/app/data/raw`. В PowerShell вместо `$(pwd)` — `${PWD}`.

Абляция E1 (без собственных записей): выставить `use_nt: false` в
`configs/default.yaml` и перезапустить обучение.

## Отдельные шаги

```bash
# только препроцессинг (librosa) и сборка манифеста
docker run --rm -v /mnt/d/AML_labs/sound:/app/data/raw -v $(pwd)/data:/app/data \
  lab-aphasia python scripts/preprocess_audio.py

# только обучение
docker run --rm --gpus all -v $(pwd)/data:/app/data -v $(pwd)/checkpoints:/app/checkpoints \
  lab-aphasia python -m src.train --config configs/default.yaml

# только визуализация отчёта (EDA + confusion matrix + ROC + карта attention)
docker run --rm --gpus all -v $(pwd)/data:/app/data -v $(pwd)/reports:/app/reports \
  -v $(pwd)/checkpoints:/app/checkpoints \
  lab-aphasia python -m src.report --config configs/default.yaml

# инференс одной фонограммы
docker run --rm --gpus all -v $(pwd)/data:/app/data -v $(pwd)/checkpoints:/app/checkpoints \
  lab-aphasia python -m src.inference --wav data/processed/aphasia/aphasia_sp10_m_0_cma_s_22.wav
```

> **Важно про конфиг:** `configs/` копируется внутрь образа при сборке
> (`COPY . .`). Если `configs/default.yaml` отредактирован после
> `docker build` (например, `use_nt: false` для абляции E1), добавь в команду
> запуска маунт `-v $(pwd)/configs:/app/configs` — иначе контейнер прочитает
> старую копию конфига из образа.

## Файлы

- `src/model.py` — архитектура cross-attention фузирования
- `src/metadata.py` — парсинг метаданных из имён файлов (3 схемы именования)

- `src/report.py` — EDA (возраст, типы афазии, источники) + визуализация результатов

- `scripts/make_synthetic_data.py` — синтетика для smoke-теста

- `configs/default.yaml` — все гиперпараметры в одном месте

## Ограничения и что можно улучшить

- **Возраст**: все участники эксперимента 40+ (молодые — редкие исключения),
  поэтому выраженного возрастного конфаунда нет; распределения классов по
  возрасту (где он указан) перекрываются. У части пациентов возраст в имени
  файла не указан (0) — такие записи исключаются из возрастного графика
  в `eda.png`, но не из обучения.
- Записи длинные (до ~25 мин), модель видит первые `max_audio_sec` секунд
  (по умолчанию 300 с — ограничение VRAM при фузировании, а не энкодера:
  wav2vec2 прогоняет запись фрагментами и мог бы дальше). Для большинства
  записей пациентов (100–400 с) этого достаточно; самые длинные контрольные
  обрезаются. Дальнейшее развитие — иерархическая агрегация фрагментов.
- Whisper-small может ошибаться на афатической речи — транскрипты частично
  шумные; при наличии ручных транскриптов кладите `<имя>.txt` рядом с аудио.
- В фолдах с 2–3 контрольными дикторами в test разброс метрик неизбежен —
  поэтому главный результат агрегируется как OOF по всем дикторам.
